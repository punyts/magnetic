# Changelog

## 0.1.0 (unreleased)
- **Fix: one maker of the statenet authority's key.** On an empty database two servers and `relay-certificate` each
  inserted a key and read back the oldest by `created_at`, which a later-committed insert with an earlier time could
  change after another had already signed with its own. `StatenetAuthority.keys()` now looks and inserts under a
  database advisory lock (`statenet-authority`, `databaseExclusive`), taken only when no key is found: the first holder
  makes the key and the others read it, so one row is ever made. Test: `src/statenet/StatenetAuthority.test.ts`
  ("should make one key when several processes ask at once on an empty database…").
- **The ids made for a page's marked nodes no longer depend on the order of the tree.** `ownTree` gave a marked node
  without an `@id` the shortest ending of its keys not yet used, so the first node keyed `notice` was `noticePart`,
  and a same-keyed marked node added before it took that id from it; copies of pages keep ids. The rule is now
  `generatedIds` (`src/pages/own.ts`): a node's chain is the keys of the nodes from its screen's name down to it, its
  names are the chain's endings in camel case with `Part` (`noticePart`, `barNoticePart`, `homeBarNoticePart`), and
  its id is its shortest name that is no name of any other marked node, no `@id` and no node's key. Two nodes with the
  same key both take a longer name; a node added later renames another only when one of its names is the id the other
  had. A screen's marked root is `<screen>Part` (it was `Part`). Breaking: ids change once, for nodes that share a
  key with another marked node (`noticePart` beside a `bar.notice` is `homeNoticePart`); a person's changed copy
  with an old id loses those writes until it is reset. Tests: `src/pages/own.test.ts` ("should keep the id made for a
  node when a marked node is added elsewhere…", "should make an id from the keys of the node alone…").
- **The page scripts' `ownWrites` is the text of the server's.** `OWN_JS` (`src/pages/own.ts`) was a hand copy of
  `ownWrites`; it is now `ownWrites.toString()`, so the two cannot differ. The function is self-contained (it uses only
  its arguments) and takes an optional `place`: with it a place is the state path the caller gives (`PageSpec`'s
  sample, `HomeApps.show`); without it a place is the node by id, `#<id>.<property>`, marked `optional`, which is what
  the pages write. A write keeps whatever else it carries. Breaking: `ownWrites(own, writes)` without `place` now
  answers the `optional: true` the page script always did. Test: `src/pages/own.test.ts` ("should give the page
  scripts the text of ownWrites itself, which runs alone and answers the same"), which runs the script text in a
  context of its own and fails when it stops defining `ownWrites`.
- **Fix: Your apps applies the fields that are a node's own state.** `HomeApps.show` looked for the node of each such
  field (`notAdmin`, `noInvites`, `noRequests`, `noMakeOrg`, `usageTone`: `HOME.own`) in the state of the person's
  instance, which holds only what was written to it and so no nodes: every such write was dropped, and the Admin link,
  the invites and the line of waiting requests never showed. The node is now found by its `@id` in the document of the
  person's copy (`instanceViews.message(app, 'attach').document`), wherever they moved it, and
  `<path>.<property>` is written to the instance. A value the instance never held is compared with the one the document
  defines, so a load that changes nothing still writes nothing; a copy without the node drops the write. Covered by
  `src/home/HomeApp.test.ts` and the e2e specs for the Admin link, invites and requests.
- **The editor's data is in namespaces, a record for each part of the editor.** `$.data.editor` (one model,
  `magnetic-editor`, of several dozen unrelated fields) is gone. The editor's data is eleven records, each with a
  model (`magnetic-editor-<namespace>`) and a binding of its own (`RECORDS` in `src/editor/EditorApp.ts`): `app`
  (the app's name and workspace, the notice, whether it is blank), `chat` (status and data lines, focus and context
  chips, the model, the agent's note, agent use), `inspector` (status, heading, breadcrumb, tab, the state path's
  detail), `sharing`, `preferences`, `feedback`, `canvas` (view, frame size, zoom), `rail` (tool, layers, the
  buttons' looks), `screensPanel`, `connectionsPanel` and `sharedPanel`. The lists (`messages`, `calls`,
  `links`, `components`, `screens`, `connections`, `shared`, `paths`, `feed`) are as they were. Fields keep their
  names, and a name is in one namespace only: `EDITOR_FIELDS` maps each to its data path (`status` to
  `$.data.chat.status`), is made from the models, and is in `/assets/shell.js` as `FIELDS`, so the scripts still
  write `ed({ status })` and `editor.set({ … })`; a name the editor does not have now throws there. A pane's flag
  (`chatHidden`) maps under `$.data.panes`, which is no data: `EDITOR.own` takes it to the pane's own `hidden` by id.
  `pageSpec` takes `records` (a list of `{ path, model }`) in place of `record`, and `ownTree(definition, models,
  records)` takes each `own:` field out of the model of its record; a field named without a path is the first
  record's that has it. Breaking: `$.data.editor` and the model `magnetic-editor` are no more, a person's changed
  copy of the editor keeps the old paths until they reset it, and `PageSource.record` and `ownTree`'s `base` and
  `model` arguments are replaced. Tests: `src/editor/EditorApp.test.ts` (each field in one namespace with a model
  and a binding, the panes' flags), `src/pages/own.test.ts` (two records), `src/pages/ownState.test.ts`, and the
  e2e suite over the editor.

- **Connections: apps call outside APIs** (M8, N6).
